# TC25079: Tags Management (API)

**Azure Test Case:** 25079
**Suite:** AdminSystemSettings-25155
**Thunderclient:** ❌ Not yet implemented
**Test Users:** 9200-9299 range (API test users with admin roles)

---

## What This Tests

Tags can be created, read, updated, and deleted via API with proper database persistence. Tags can be linked to Core Tasks, Diverted Tasks, and Downtime with correct relationship storage.

---

## Test Checklist

### Create Tag
#### Request
- Method: POST
- Endpoint: `/api/admin/tags`
- Body:
  ```json
  {
    "name": "Test Tag",
    "description": "Test description"
  }
  ```

#### Response Checks
- [ ] Status code is 201 Created
- [ ] Response contains entity with ID
- [ ] Name matches request

#### Database Checks
- [ ] **Tag table:**
  - Record exists with returned ID
  - Name matches request
  - Description matches request
  - CreatedDate is recent
  - IsActive = 1

---

### Get All Tags
#### Request
- Method: GET
- Endpoint: `/api/admin/tags`

#### Response Checks
- [ ] Status code is 200 OK
- [ ] Response is array of Tags
- [ ] Created entity is in the list

---

### Get Single Tag
#### Request
- Method: GET
- Endpoint: `/api/admin/tags/{id}`

#### Response Checks
- [ ] Status code is 200 OK
- [ ] Response contains entity with correct ID
- [ ] All fields populated correctly

---

### Update Tag
#### Request
- Method: PUT
- Endpoint: `/api/admin/tags/{id}`
- Body:
  ```json
  {
    "id": "{entityId}",
    "name": "Updated Tag Name",
    "description": "Updated description"
  }
  ```

#### Response Checks
- [ ] Status code is 200 OK
- [ ] Name updated correctly

#### Database Checks
- [ ] **Tag table:**
  - Name updated to new value
  - Description updated
  - ModifiedDate is recent

---

### Link Tag to Core Task
#### Request
- Method: POST
- Endpoint: `/api/admin/tags/{tagId}/coretasks` (or `/api/admin/coretasks/{taskId}/tags`)
- Body:
  ```json
  {
    "coreTaskId": "guid"
  }
  ```

#### Response Checks
- [ ] Status code is 200 OK or 201 Created
- [ ] Response confirms link

#### Database Checks
- [ ] **TagCoreTask (or similar) table:**
  - Link record exists
  - TagId and CoreTaskId match
  - IsActive = 1

---

### Link Tag to Diverted Task
#### Request
- Method: POST
- Endpoint: `/api/admin/tags/{tagId}/divertedtasks`
- Body:
  ```json
  {
    "divertedTaskId": "guid"
  }
  ```

#### Database Checks
- [ ] **TagDivertedTask table:**
  - Link record exists
  - TagId and DivertedTaskId match

---

### Link Tag to Downtime
#### Request
- Method: POST
- Endpoint: `/api/admin/tags/{tagId}/downtime`
- Body:
  ```json
  {
    "downtimeId": "guid"
  }
  ```

#### Database Checks
- [ ] **TagDowntime table:**
  - Link record exists
  - TagId and DowntimeId match

---

### Unlink Tag from Entity
#### Request
- Method: DELETE
- Endpoint: `/api/admin/tags/{tagId}/coretasks/{taskId}` (or similar)

#### Database Checks
- [ ] **TagCoreTask table:**
  - Link soft-deleted: IsActive = 0
  - OR hard-deleted: Record removed

---

### Delete Tag
#### Request
- Method: DELETE
- Endpoint: `/api/admin/tags/{id}`

#### Response Checks
- [ ] Status code is 200 OK or 204 No Content

#### Database Checks
- [ ] **Tag table:**
  - Soft-deleted: IsDeleted = 1 OR DeletedDate set
  - OR hard-deleted: Record removed
- [ ] **All tag link tables:**
  - Related links also removed or marked inactive

---

### Edge Cases
- [ ] Create with duplicate name (validation error or allowed)
- [ ] Update non-existent Tag (404)
- [ ] Delete non-existent Tag (404 or idempotent 200)
- [ ] Link to non-existent task (404)
- [ ] Link same tag to same task twice (conflict or idempotent)
- [ ] Delete tag with existing links (cascade delete or prevent)

### Cascade Deletion
When a Tag is deleted:
- **Option A:** All links automatically removed (cascade delete)
- **Option B:** Deletion prevented if links exist
- **Option C:** Soft delete tag, links remain but inactive

This affects database verification queries.
